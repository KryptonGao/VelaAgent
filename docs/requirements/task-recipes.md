# 任务配方需求文档

状态：P0、P1、P2 已在当前开发分支实现，尚未随版本发布。实现对照、验证与剩余项见 [任务配方](../task-recipes.md)。  
日期：2026-10-04。  
范围：Vela 桌面端可填写参数、预览并重复使用的任务流程。  
产品名称：任务配方；英文：Task Recipes。

## 1. 产品目标

用户将经常重复的任务保存为配方。下次选择配方、填写少量参数，即可在选定工作区的新对话中开展任务。

主要流程：**选择配方 → 填写参数 → 预览本次任务 → 开始 → 在对话中查看结果。**

典型使用者是持续在一个或多个代码仓库里修复问题、审阅改动、准备发布的开发者。配方应减少重复输入，并保留每次任务的具体输入，方便回查。

首版将配方定义为包含参数、流程要求和交付要求的任务模板。步骤交由现有 Agent 解释执行；首版不提供保证逐步执行的工作流引擎，也不将模型回复结束解释为任务验收通过。

本文保留首版需求基线；P1 文件格式、信任／冲突规则与 worktree 策略见 [P1 增强功能](../task-recipes.md#p1-增强功能)。P2 的阶段状态机、副作用／重试边界、团队权限与统计口径见 [P2 阶段、共享与效果比较](../task-recipes.md#p2-阶段共享与效果比较)。

## 2. 当前实现基线与能力关系

以下基线记录实施前的会话与工具能力；后续章节保留需求基线。当前实现及边界见 [需求对照](../task-recipes.md#需求对照)。

| 能力 | 当前实现依据 | 与配方的关系 |
| --- | --- | --- |
| Skill | `packages/agent/src/skill-catalog.ts` 的 `loadSkillCatalog`；`packages/agent/src/skill-management.ts` 的 `setSkillEnabled` | Skill 提供可复用方法；配方提供本次任务的目标、参数和流程。配方不复制一套 Skill 加载机制。 |
| 新对话与发送 | `packages/agent/src/runtime.ts` 的 `createConversation`、`prompt` | 配方通过现有会话运行时执行，不引入另一套模型或工具执行链。 |
| Agent / Plan / Goal | `packages/agent/src/interaction.ts` 的 `toolNamesFor`、`modeSystemPrompt`；[Plan 模式](../plan-mode.md) | 配方选择启动模式；Plan 的方案修订、批准与实施继续沿用现有机制。 |
| 定时任务 | `packages/agent/src/runtime.ts` 的 `runScheduledTask`；[定时任务](../scheduled-tasks.md) | 定时任务决定触发时间；配方决定触发内容。首版只手动启动，后续再连接定时任务。 |
| 本地 / worktree | `packages/workspace/src/environment-manager.ts` 的 `ExecutionEnvironmentManager` | 配方运行绑定具体目录，首版支持已存在的本地工作区或 worktree。 |
| 运行中指令 | `packages/agent/src/runtime.ts` 的 `prompt`、`removeInstruction`；[运行中追加指令](./runtime-instructions.md) | 配方启动后，用户可沿用现有排队、调整和停止能力。 |

配方自己的流程要求以本次用户任务输入提交，不提升为系统指令，不修改工具授权。模板中的“必须执行”不能绕过 Plan 限制、工作区指令或现有执行审批。

P1/P2 不作为 P0 的隐含前置条件。首版不包含配方市场、跨项目批量执行、后台自动触发、Goal 持续执行或新的任务验收系统。

## 4. 首版用户流程

### 4.1 查找与启动

需求 ID：`TR-01`、`TR-04`、`TR-05`。

- 在左侧栏提供「任务配方」入口，打开独立管理页，页面位置和导航方式与定时任务保持一致。
- 在空闲对话的输入框提供「使用配方」入口，打开选择器；运行中的对话仍可通过配方库在新对话中启动其他任务。
- 两个入口都打开同一套参数与预览界面，并始终新建对话；不向当前聊天隐式追加配方，不复制其历史上下文。
- 配方库提供全部、内置、我的配方筛选；按名称、说明和标签搜索。默认按最近使用排序，未使用项按名称排序。
- 列表展示名称、用途、默认模式、来源和最近使用时间。无搜索结果时显示清空筛选操作。
- 首次打开时已有内置配方；用户配方为空时显示创建入口。

### 4.2 创建与编辑

需求 ID：`TR-02`。

支持从空白创建、复制现有配方，以及从一条用户或助手文本消息创建。

从消息创建时只将选中的文本放入草稿的流程要求，记录来源对话与消息引用；不自动复制整段聊天、图片或工具返回，也不从其他上下文补入路径或凭据。已选文本中的具体值原样可见，由用户决定哪些需要改为参数。用户编辑并点击保存后才进入配方库，不自动调用模型。

编辑器包含：

| 字段 | 要求 |
| --- | --- |
| 名称 | 必填，1–80 字符；同名允许存在，使用稳定 ID 区分。 |
| 说明 | 选填，最多 300 字符；说明适用任务及预期结果。 |
| 标签 | 选填，最多 5 个，每个最多 30 字符。 |
| 默认模式 | Agent 或 Plan；新建配方默认 Agent。 |
| 参数定义 | 最多 20 个；包含标识、显示名称、类型、提示、必填和默认值。 |
| 任务目标 | 必填；描述本次要完成什么，可使用参数占位符。 |
| 流程要求 | 必填；支持 Markdown 和参数占位符，写清查阅、实施与检查顺序。 |
| 交付要求 | 必填；例如结果说明、改动列表、验证结果、已知问题。 |

正文三个字段合计最多 40,000 字符。保存时校验字段、参数标识、参数默认值与占位符；默认值必须符合类型和选项规则，路径默认值的存在性留到选择工作区后检查。删除或改名参数后，正文残留的引用必须修正才能保存。失败就定位到对应字段，不保存半成品。编辑后离开页面时，如有未保存修改，提供保存、放弃或继续编辑。

用户配方可以编辑、复制、删除。内置配方只读，可复制为用户配方。删除展示配方名称与影响范围；删除后既有聊天和使用记录保留，运行中的任务继续使用自己的快照。

### 4.3 填写参数

需求 ID：`TR-03`。

首版参数类型：

| 类型 | 控件 | 规则 |
| --- | --- | --- |
| `text` | 单行输入 | 用于版本号、模块名称等短文本；最多 500 字符。 |
| `multiline` | 多行输入 | 用于问题描述、复现步骤、关注点；最多 10,000 字符。 |
| `select` | 单选 | 至少 2 个、最多 20 个选项；保存稳定值与显示名称，不接受列表外的值。 |
| `boolean` | 开关 | 明确表达是否启用某项要求；`false` 是有效值。 |
| `path` | 工作区内文件 / 目录选择器及相对路径输入 | 只允许已存在的工作区内对象；可声明只选文件、目录或两者均可。 |

参数标识匹配 `[a-z][a-z0-9_]{0,39}`，同一配方内不得重复，不得使用 `workspace` 命名空间。每个参数可配置帮助文字。文本必填按去除首尾空白后的值判断；路径解析、符号链接解析与存在性检查在主进程执行，越出实际工作区即拒绝。

必填字段未填、路径无效或选项不合法时，标记具体字段并禁用「开始」。不通过模型猜测缺失参数。

使用 `{{parameter_id}}` 引用参数；首版仅支持替换，不支持表达式、条件、循环或执行脚本。可选空值渲染为“未提供”，布尔值渲染为“是”或“否”，单选值在正文中使用显示名称。

提供 `{{workspace.name}}` 和 `{{workspace.path}}` 两个只读上下文值。未知占位符在保存与启动时拒绝。参数替换只执行一次：参数值内的 `{{...}}` 是普通文本，不递归展开。编辑器提供插入参数入口和占位符帮助。

参数只用于生成任务文字，不自动拼接到 Shell 命令或执行模板中的命令。UI 提示参数会写入本次对话和本地记录，不提供密码或 API 密钥字段。

### 4.4 预览与启动设置

需求 ID：`TR-04`、`TR-06`。

参数界面同时展示工作区、启动设置和可展开的完整任务预览，不增加第二个确认弹窗。点击「开始」就是本次启动动作。

- 工作区默认取入口所在工作区，用户可从已有工作区中改选；无工作区时必须先选择，不回退到应用内部目录。
- 切换工作区立即更新上下文值，并重新校验路径参数；不悄悄改写用户输入的相对路径。
- 模式可在 Agent / Plan 中选择，默认取配方设置。本次覆盖不修改配方。
- 模型和思考强度默认沿用应用新对话设置，也可仅为本次选择；模型不可用时提示并阻止启动，不静默回退。
- 执行权限沿用现有三档策略，默认沿用应用设置；本次修改只作用于新对话及其子代理，不修改当前聊天或应用默认值。
- 配方模板不保存模型、思考强度或执行权限，避免复制模板时附带旧账号和权限选择。
- 预览按任务目标、填写的参数、流程要求、交付要求排列，显示本次工作区与配方 revision；预览不调用模型。
- 本次补充要求使用独立输入框，追加到任务末尾并包含在预览中；P0 不支持直接编辑最终展开正文。
- 打开使用界面后固定配方 revision；其他地方保存新版本时提示有更新，可主动载入新版并重新校验，不能在点击开始时偷换内容。

关闭界面不启动任务；取消前填写的参数仅在本次应用运行内按配方与工作区保留，不写入配方默认值。重新打开时优先恢复该草稿，否则使用默认值。草稿不包含权限覆盖；已有权限覆盖在关闭后丢弃。

### 4.5 开始与对话体验

需求 ID：`TR-05`。

1. 主进程重新校验配方快照、参数、目录、模型和启动设置，生成与预览一致的任务正文。
2. 保存使用记录和本次快照，再创建绑定目标目录的新对话；绑定成功后保存对话 ID。
3. 应用模式和启动设置，提交一次用户任务输入，并切换到新对话。
4. 首条消息展示配方名称、revision、参数摘要与展开任务正文。历史恢复后仍能查看，不把配方元数据重复作为另一条模型消息。
5. 后续工具调用、审批、提问、排队、调整、停止、diff 和轨迹沿用现有会话能力。

对话初始标题为「配方名称 · 工作区名称」，之后允许用户修改；本次补充要求不自动变更配方。新对话不继承来源聊天的消息，项目规则、已启用 Skill 和 MCP 仍按目标工作区的现有机制加载。

Plan 配方只开展规划。输出方案后由用户通过现有 Plan Document 批准实施；「开始配方」不自动批准方案。批准后的执行对话继续使用现有 Plan 关联方式，首版配方记录只追踪最初启动回合，不另造跨对话编排。

首版不新增步骤进度条。模板里的步骤表示流程要求，实际执行顺序和结果通过对话与轨迹查看，不按生成的文字推断完成百分比。

## 5. 使用记录与版本规则

需求 ID：`TR-07`、`TR-08`。

每次保存正文、参数定义、名称、说明、标签或默认模式的变化都增加 revision；首次为 1。无变化保存不增加 revision。复制配方生成新 ID，revision 从 1 开始。

每次使用保存完整配方快照、参数、补充要求、实际目录、展开正文、实际模型 / 思考强度 / 权限、触发时间和对话 ID。执行开始后固定这些值；修改或删除原配方不改变既有任务。

配方详情中提供使用记录，默认每页 20 条，展示时间、工作区、revision、模式、状态与打开对话入口。首版不自动裁剪记录。对话被删除后显示“关联对话已删除”，仍可查看快照。

| 状态 | 含义与展示 |
| --- | --- |
| `starting` | 正在创建并绑定对话，尚未提交任务。 |
| `running` | 初始配方回合正在生成或使用工具。 |
| `waiting_for_user` | 初始回合等待现有审批或提问机制的响应；回应后返回 running。 |
| `responded` | 初始回合正常结束，显示“回复已生成”；Plan 产生草稿时额外显示“方案待审阅”。不显示“验收通过”。 |
| `failed` | 创建、提交或初始回合出现运行时错误；保留失败原因。 |
| `stopped` | 用户主动停止初始回合。 |
| `interrupted` | 应用退出或崩溃导致初始回合未结束。 |

终态记录初始回合的结束时间。用户在同一聊天继续提问、修复或批准计划不改写旧记录状态；详情提示后续进展见聊天。不从助手自然语言判断工具失败或业务结果，单个工具错误被 Agent 处理后也不必导致整条记录 failed。

「再次使用」打开原快照与参数的使用界面，工作区默认沿用原记录，重新校验并再次预览；模型和权限默认使用当前应用设置，不继承旧权限覆盖。它不是恢复执行，不自动重放命令。原配方仍在且存在新版时，可选择载入最新版并重新匹配参数；不存在时可继续使用原快照或另存为新配方。

快照固定配方内容，不冻结工作区文件、Skill 正文或 MCP 工具版本；再次使用仍读取当时目标工作区的资源。

## 6. 内置配方

需求 ID：`TR-09`。

首版交付三个中文内置示例，英文界面提供对应翻译。每个配方均包含参数、流程要求、交付要求和适用说明。

| 配方 | 默认模式 | 参数 | 流程要求 | 交付要求 |
| --- | --- | --- | --- | --- |
| 修复 Bug | Agent | 问题描述（必填）、复现步骤、预期行为、关注路径 | 查明原因 → 限定修复范围 → 实施 → 按风险验证；无法复现时说明证据缺口 | 根因、改动、实际验证和剩余问题；不默认要求全量测试。 |
| 审查改动 | Plan | 审查范围（未提交改动 / 两个 Git 引用）、起始引用与结束引用、关注点 | 查阅差异和相关代码 → 检查正确性及回归风险 → 汇总发现；不自动修复 | 按严重程度列出问题、文件位置、触发条件和建议；未发现问题也说明检查范围。 |
| 准备发布 | Agent | 目标版本（必填）、起始引用（必填）、结束引用（默认 HEAD）、补充说明 | 核对版本规则与提交范围 → 整理发布说明草稿 → 列出需要的检查和发布步骤 | 发布说明草稿、版本差异和待完成事项；该配方只准备材料，不要求创建 Tag、推送或发布。 |

内置 Git 参数具有额外语义校验：选择两个引用的审查必须同时填写起止引用；未提交改动包含索引与工作区差异，列出未跟踪文件，并注明查看范围。发布和双引用审查在启动时校验引用有效并保存解析后的提交 SHA；使用明确的起始提交与结束提交比较，不自动改成 merge-base 比较。等待表单期间 HEAD 或工作区状态有变化时更新预览摘要，再由用户点击开始。

自定义配方的普通 text 参数不自动按 Git 引用解释。内置 Git 预检基于类型化查询执行，不把文本插入 Shell 字符串。非 Git 目录仍可使用自定义配方及修复 Bug；Git 审查和发布配方在参数界面解释缺少仓库条件。

内置配方随应用提供稳定 ID 和内置版本。应用升级可以更新内置模板，既有使用快照和用户复制件不被覆盖。内置配方也不能凌驾于项目指令和用户本次补充要求。

## 7. 异常、并发与恢复

需求 ID：`TR-10`。

- 提交期间禁用重复点击；每次提交携带唯一 requestId，主进程以 requestId 去重。同一请求只创建一个使用记录、一个对话并提交一次正文。
- requestId 绑定首次提交的输入摘要；相同 ID 携带不同内容时拒绝。创建对话前预留并持久化目标 conversationId；创建操作必须可按该 ID 对账，不能在绑定写入失败后再次分配 ID。结果无法确认的请求停止重试并标记中断，交给用户检查。
- 在没有副作用的预检阶段失败，不创建对话。保存记录失败则不创建对话、不启动 Agent，并保留表单供重试。
- 创建成功但绑定记录或提交失败时保留已创建的对话 ID，停止后续提交，展示实际状态；重试同一 requestId 不再创建第二个对话。
- 主进程必须先持久化发送意图，再提交消息。崩溃恢复时，即使无法判定消息是否已经发出，也标 interrupted 并保留对话；不自动重发，不承诺外部操作 exactly-once。
- 启动前目录消失、路径参数改变、模型失效或 Git 引用解析结果变化时，停止启动并更新预览；不得静默改工作区、参数或模型。
- 初始回合停止后保留聊天、已完成工具操作和记录，不自动回滚工作区或外部操作。
- 重启后，starting / running / waiting_for_user 记录转为 interrupted；可打开聊天检查，或再次使用快照。不自动恢复执行。
- 允许同一配方在不同工作区并发。同一实际工作区已有运行中聊天时，在使用界面提示可能同时修改文件；用户仍可通过正常开始操作启动，配方系统不声称提供文件隔离。
- 配方正文与参数经过主进程校验；renderer 不能通过自造模式或权限值调用不存在的执行策略。
- 配方库读取失败应展示错误与重试，保留原文件，不以空库自动覆盖；未知 schemaVersion 提示不兼容并停止写入。

## 8. 数据与实现边界

以下为拟新增模型与落点，不代表已有接口。

| 模型 | 核心字段 |
| --- | --- |
| `TaskRecipe` | id、origin、revision、name、description、tags、defaultMode、parameters、objectiveTemplate、workflowTemplate、deliverableTemplate、sourceReference、createdAt、updatedAt。 |
| `RecipeParameter` | id、label、type、help、required、defaultValue；select 的 options；path 的 pathKind。 |
| `RecipeUseDraft` | 固定的 recipeSnapshot、workspace、values、additionalInstructions、mode、modelOverride、thinkingLevelOverride、sandboxModeOverride。 |
| `RecipeRun` | id、requestId、recipeId、recipeSnapshot、values、additionalInstructions、resolvedContext（含 Git SHA）、expandedPrompt、workspace、resolvedExecution、conversationId、status、startedAt、finishedAt、error。 |

- 用户配方与使用记录保存到 Vela 资料目录的 `task-recipes.json`，包含 schemaVersion；内置定义随应用打包，不写入可编辑的用户模板集合。
- 主进程是 CRUD、展开、预检、启动和记录状态的权威来源。写入串行化并使用临时文件原子替换，关键启动步骤必须等待落盘成功。
- 配方元数据不与模型 API 凭据合并保存；沿用 `VELA_USER_DATA` 目录覆盖规则。
- `packages/shared` 定义独立类型与 IPC 契约；renderer 负责配方库、编辑、表单和预览。
- 参数验证与正文展开使用可独立测试的逻辑；实际执行复用 `packages/agent/src/runtime.ts` 的会话机制，避免把 UI 展开的文字直接视为可信输入。
- 使用记录属于配方服务；聊天中的配方卡通过 runId 关联记录。原模板不存在时卡片仍读取快照。
- 启动返回 runId 与 conversationId；持续状态通过事件更新。结束状态依据初始调用、停止信号和真实审批 / 提问事件，不靠扫描最终回复。
- P0 不注册模型可自行触发的配方工具，不自动创建 Skill 文件，不对普通聊天或现有定时任务改变默认行为。

下列场景用于首版验收。当前自动验证使用临时工作区及合成模型响应，范围见 [验证与边界](../task-recipes.md#验证与边界)。

| 验收 ID | 需求 ID | 场景 | 预期结果 |
| --- | --- | --- | --- |
| TRA-01 | TR-01 | 首次打开、搜索与来源筛选 | 三个内置配方可用；用户空库与搜索空结果有明确操作。 |
| TRA-02 | TR-02 | 新建、保存、编辑、复制、删除 | 字段校验有效；修改增加 revision；复制有新 ID；内置模板不可覆盖。 |
| TRA-03 | TR-02 | 从一条消息创建 | 仅选中文本进入草稿；未保存不入库；不复制其他聊天内容、不调用模型。 |
| TRA-04 | TR-03 | 各类参数与非法输入 | 必填、默认值、false、选项、长度及未知占位符在 UI 和主进程均正确处理。 |
| TRA-05 | TR-03 | 路径越界、符号链接、工作区切换 | 越界和失效路径被拒绝；切换后重新校验，不偷偷重写值。 |
| TRA-06 | TR-03、TR-04 | 参数含换行、引号、反引号、`{{...}}` 或 Shell 文本 | 只进行一次文字替换，预览与实际正文一致；展开过程没有命令执行。 |
| TRA-07 | TR-04 | 预览时配方更新、HEAD 改变或模型不可用 | 快照不被替换；上下文变化必须重新预览；不可用模型不静默回退。 |
| TRA-08 | TR-05、TR-06 | 两个入口分别启动 Agent 配方 | 均新建正确目录的聊天，正文只提交一次；设置覆盖仅作用于新聊天及其子代理。 |
| TRA-09 | TR-05、TR-06 | 启动 Plan 配方 | 保持现有只读限制，产出方案后仍通过既有批准流程实施，无自动批准。 |
| TRA-10 | TR-07、TR-08 | 运行中修改或删除配方，随后重启 | 聊天和快照可查；既有运行内容不变；记录能打开对应聊天。 |
| TRA-11 | TR-08 | 正常回复、提问、审批、错误、停止 | 状态由真实事件更新；正常回复只表示回复已生成；后续聊天不改写初始记录。 |
| TRA-12 | TR-08 | 再次使用旧记录 | 先打开原快照预览；重新校验；采用当前默认权限；不立即执行。 |
| TRA-13 | TR-09 | 三个内置配方与非 Git 工作区 | 参数和交付要求完整；Git 范围明确并保存 SHA；发布配方不要求实际发布。 |
| TRA-14 | TR-10 | 双击开始、重复 IPC、绑定失败 | 一个 requestId 仅产生一条记录、一个对话和一次提交；失败保留实际对话关联。 |
| TRA-15 | TR-10 | 在发送前后不同时间崩溃 / 退出 | 重启标 interrupted，原快照和已知对话 ID 保留，不自动重发。 |
| TRA-16 | TR-10 | 保存失败、数据损坏或未知版本 | 不启动任务、不覆盖原库，有可理解的错误与重试入口。 |
| TRA-17 | TR-04、TR-10 | 同目录并发与切换工作区 | 展示并发提示；每次绑定其启动目录，不受当前选中项目变化影响。 |

## 11. 实施顺序与验证策略

建议按下面顺序实现，每一阶段均以相关验收项为完成依据：

1. 配方模型、参数验证、单次展开、版本快照与存储（TR-02、TR-03、TR-07）。
2. 配方库、编辑器、表单预览和内置配方（TR-01、TR-04、TR-09）。
3. 新对话启动、设置作用域与记录关联（TR-05、TR-06、TR-08）。
4. 重复请求、失败恢复、重启与异常状态（TR-10），完成 P0 验收。

需求最初起草时只有文档与索引，属于低风险；首版实际实现涉及持久化、IPC 与会话生命周期，按高风险改动验证，详见实现文档。

实际实现涉及持久化、IPC 和会话生命周期，属于高风险。先测参数展开、版本快照、存储故障、去重与中断恢复，再测会话启动、权限作用域和 Plan 只读边界；进行受影响包的类型检查与构建，以及真实 Electron 流程验收。共享运行时修改时补相关会话、Plan、审批与定时任务回归；仅当影响扩散到全仓或定向验证不足时运行全量回归，遵循仓库的风险分级验证政策。

## 12. 产品验收后的观察指标

首版不设没有依据的数值目标，先记录基线并观察：

- 从打开使用界面到提交任务的耗时、取消率和校验错误率。
- 用户配方被再次使用的次数，及三个内置配方的使用分布。
- 启动失败与重复创建次数；同一 requestId 重复创建的验收目标为 0。
- 用户启动后需要补充多少任务信息，以及失败后是否能通过记录找回对话。

首版只根据本机数据查看这些信息，不引入远程遥测。`responded` 比例不作为任务成功率。
