# Agent Inbox 与常驻 Agent 需求

**状态：** 第一至第七阶段均已实现。已实现部分的行为、限制和实现位置见 [../agent-inbox.md](../agent-inbox.md)。

## 定位

Agent Inbox 是独立于对话的一级工作空间，承担四件事：**接收**各工作区的事件，**决策**用户问题与工具授权，**协调**后台任务，**交付**结果。核心原则是 Agent-first、Inbox-centered、User-controlled：Agent 可以主动提出建议，但不会因此获得额外权限；界面负责展示和收集意图，主进程决定是否执行；后台任务不依赖 React 页面是否挂载。

不得为 Inbox 另建 Scheduler、Agent Loop 或工具执行引擎，必须复用 `AgentRuntime`、`AgentControl`、`SessionHost`、`ScheduledTaskScheduler`、`TaskRecipeService`、沙箱权限与 Intelligent UI。

## 范围分级

**P0 Foundation**：一级页面；Overview、Needs Action、Activity、Archive；Resident Agent 持久会话与手动提交；接入真实审批与提问；接入定时任务与 Agent 完成事件；状态持久化；主窗口隐藏后的后台行为；通知与静默规则；Host 权威决策；原生 Intelligent UI 渲染；崩溃恢复与过期审批保护。

**P1 Proactive Intelligence**：用户可配置的事件订阅、Git 与工作区触发器、智能合并通知、主动建议、任务依赖协调、预算管理、更丰富的完成报告、可解释的触发原因。

**P2 Extended Autonomy**：多设备同步、可选的 Remote Agent、更多外部事件、条件式长期监控、任务自动编排、跨设备交接。P2 不是 P0 的前提。

## 关键约束

- **决策权在 Host。** Agent 生成的 Intelligent UI 不能批准工具；`submit_to_agent` 不是 `approve_tool`。真实审批由 Host 渲染，经 Preload 交给主进程，主进程校验请求、权限与版本后才回复，成功后才更新状态。
- **归档不等于决策。** 阅读状态与业务状态独立，归档待决审批不会同意、拒绝或解除阻塞；不提供危险审批的批量同意。
- **先落盘、后通知。** 重启后无法真实恢复的等待点必须标为失效，不能因为保留了卡片就声称原调用还能继续；不自动重放可能已产生外部副作用的工具操作，也不承诺 exactly-once。
- **不扩大权限。** 后台运行不放宽已有的 Ask Every Time、Approve for Me、Full Access，也不因 Resident Agent 有全局入口就授予全局文件系统权限；未授权工作区的源码不得进入它的上下文。
- **待命不耗模型。** 没有有效事件时不周期性调用模型；用户暂停后不再启动新的主动任务。
- **本地桌面的真实边界。** 窗口隐藏而主进程存活时可继续执行；系统睡眠、应用退出、关机后本地 Agent 停止；P0 不承诺云端全天候执行。

## 后续阶段的设计决定

- Resident Agent 默认是不绑定工作区的协调者。**由用户在输入区明确选择工作区**，提交后通过该工作区现有的 Agent Runtime 创建后台对话，权限沿用该工作区的设置，结果回到 Inbox。暂不提供让 Agent 自己提议并委派任务的 `delegate_task` 工具。
- Intelligent UI 复用现有 `vela-ui` 解析器、组件注册表和状态存储，不新建 DSL。状态依赖会话、消息位置序号（`u{n}`）和内容指纹，Inbox 必须引用真实 `conversationId` 并复用同一套序号规则；后台生成的 UI 需要保存可重建的原始内容。
- 后台模式提供 Disabled、Standby、Proactive 三档，默认 Standby；Proactive 需要用户明确开启，规则必须告知可能产生的模型调用与费用，并带有去重、冷却、限速与并发保护。
- 需要时再评估把存储换成事务型数据库；在此之前沿用带版本的 JSON 与原子写入。

## 验收标准

**页面与交互**：Agent Inbox 作为一级页面独立存在；可从任意对话切换，且不停止运行中的 Agent；待处理徽标数量正确；列表与详情始终指向同一事项；明暗主题与五种语言兼容；窄窗口可用并支持键盘与读屏。

**事项与审批**：子代理以外的真实审批与问题进入全局 Inbox；回答后恢复正确的原始等待点；两处同时审批只有一个成功；已过期的请求不能执行；审批结果与 Host 状态一致；归档不同意工具权限；应用重启后未决事项仍可查看，不可恢复的等待请求正确失效。*（以上已实现。）*

**Agent 与后台**：Resident Agent 有稳定可恢复的会话；隐藏渲染层后后台执行继续；退出后不宣称 Agent 在线；睡眠、唤醒和离线有明确状态；多 Agent 并行不互相阻塞；空闲待命不产生模型请求。*（已实现；登录启动只在安装版有效。）*

**Intelligent UI 与安全**：复用现有协议与组件；Resident Agent 能生成 UI；非法 UI 安全降级；动态 UI 不能绕过真实工具审批；没有已知的权限升级入口。*（已实现：界面动作只是普通消息，真实审批只由 Host 控件完成。）*

## Definition of Done（P0）

用户在普通对话中启动任务并切到 Agent Inbox，任务继续运行；Agent 需要回答或审批时事项进入 Inbox；用户在 Inbox 查看完整上下文，借助 Intelligent UI 分析建议，并通过可信的 Host 操作完成决策；原 Agent 收到正确回答继续执行；任务完成后真实结果、状态和证据回到 Inbox；窗口隐藏、页面切换和应用重启过程中状态不被错误表示，过期权限不会被重复执行；Resident Agent 在不持续消耗 Token 的情况下待命，收到有效事件后协调已有 Agent Runtime。
