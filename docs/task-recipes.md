# 任务配方

状态：P0、P1、P2 已随 0.1.7 发布。日期：2026-10-05。需求基线见 [任务配方需求](./requirements/task-recipes.md)。

任务配方保存任务目标、参数、流程要求和交付要求。选择配方、填写参数并查看预览后，点击「开始」会在指定工作区的新对话中提交一次任务。未定义结构化阶段时，步骤由现有 Agent 在单次任务中解释执行；定义阶段后，Agent 模式由运行时按阶段逐次提交，Plan 仍只生成整体方案。阶段回复结束不表示任务验收通过。

## 使用方式

侧栏「任务配方」打开独立管理页。输入 `/` 时，斜杠菜单按「技能／任务配方」分组展示，配方可按名称、说明或标签搜索，并用方向键、Enter／Tab 或点击选择。选择配方会移除当前斜杠查询并打开参数预览表单，保留其余聊天草稿，不立即发送或启动任务；运行中的聊天不展示配方选项。支持全部、内置、我的配方、项目配方筛选与名称、说明、标签搜索；按最近使用排序。三个内置示例是修复 Bug、审查改动、准备发布，并提供英文模板。内置模板只读，可以复制为个人配方。

可以从空白、现有配方副本或一条用户／助手文本消息创建配方。消息上有文本选区时只采用该选区，否则采用该条消息的文本；不复制其他消息、图片、工具结果或隐藏思考，默认不调用模型；也可从 Plan Document 的当前修订创建草稿。内容先进入编辑器，保存后才加入配方库。

编辑器提供参数标识、显示名称、类型、帮助、必填、默认值、单选选项和路径类型。正文使用 `{{parameter_id}}`、`{{workspace.name}}`、`{{workspace.path}}`；插入入口会插到所选正文的光标位置。删除参数后必须修正引用。未知或不完整占位符不能保存，默认值也必须符合类型和选项规则。

使用界面固定配方 revision，支持已有本地工作区和 worktree。可覆盖本次模式、模型、思考强度和执行权限，并填写本次补充要求；这些内容都进入预览。权限覆盖只作用于新聊天及其子代理，不改应用默认值；输入框权限菜单显示该聊天的固定快照。取消时仅在当前应用进程内缓存参数和设置草稿，权限覆盖不缓存。再次使用历史记录先打开原快照，模型和权限采用当前默认值。

主进程再次校验路径、模型和 Git 范围，并比较预览指纹。目录、路径对象、Git HEAD／范围／工作区差异或解析后的启动设置变化时，启动被阻止；界面更新预览，用户再点击开始。校验期间的参数、目录和设置不会悄悄改写。Git 工作区变化每两秒重新查询；单个查询最多十秒，较大的差异超出查询上限会显示预检错误，不按截断数据启动。

Plan 配方保持现有只读限制，产生方案后仍通过 Plan Document 批准实施。准备发布只整理材料，不要求创建 Tag、推送或发布。配方正文作为用户消息提交，不能提升指令优先级或改变已有工具授权。

## P1 增强功能

- **AI 整理（TR-11）**：编辑器的「AI 整理配方」展示将发送的完整原文，并要求选择可用模型。可以采用选定消息、Plan Document 的某个修订或粘贴的计划；仅发送原文，不读取其他消息、工具结果或隐藏思考。独立模型调用不提供工具，支持取消与超时；输出经参数和占位符校验后回填草稿，用户保存后才入库。计划来源默认保持 Plan，可手动改选模式。无效输出保留原草稿，不自动补齐。
- **项目库与交换（TR-12）**：新建或复制时选择个人库或已有项目。项目模板在项目根目录的 `.vela/task-recipes.json`，格式为 `schemaVersion: 1` 与 `recipes` 数组，最多 100 项；每项含模板、UUID、revision 与创建／更新时间。文件中的 UUID 可随项目复制，应用按真实项目目录生成独立身份，跨项目重名不会覆盖。未知版本、损坏、超限或符号链接存储拒绝写入；错误只阻止对应项目，不覆盖个人库。编辑已有模板保持原保存位置，转存请复制。外部改动通过「刷新」、窗口重新获得焦点或下次定时触发读取。
- **导入导出（TR-12）**：交换 JSON 使用 `format: "vela-task-recipes"`、`schemaVersion: 1` 与 `recipes` 数组；单文件最多 4 MB、100 项。只包含模板，不包含使用记录、模型、权限、来源聊天引用或内置 Git 特权。先完整校验，再展示未保存的导入清单；逐项进入编辑器审阅正文与 Skill 名称，显式保存时生成新 ID 和 revision 1。导入不运行任务，重名不覆盖；内置导出后作为普通自定义模板导入。
- **Skill 依赖（TR-13）**：编辑器以每行一个名称声明 `requiredSkills`，最多 20 个唯一名称。预览和发送前通过目标工作区现有 Skill 目录解析，列出缺失、停用或不可读项并阻止启动，不下载、启用或调整权限。展开正文列出所需名称，本次上下文记录解析位置与正文指纹；等待期间 Skill 内容变化使预览失效。快照不冻结 Skill 文件。
- **定时绑定（TR-14）**：参数与完整预览有效后，点击「绑定定时任务」。保存当前配方快照、固定参数、补充要求、模式与所选启动设置。版本策略默认「固定此版本」；可明确选择「每次跟随新版」。固定版本在模板修改或删除后仍可用；跟随新版在每次触发读取最新模板、补入新增参数默认值并重新校验，删除、参数不兼容或 Skill 不可用时该次失败，不猜测值。复用定时任务的周期、时区、错过、并发和重启中断策略；执行期间持有原调度锁，同时写入两种使用记录，后台创建聊天不切换当前聊天。定时页面可查看快照与参数、修改时间／版本策略、暂停或删除；更换绑定参数需重新创建绑定。定时绑定使用已有工作区，不自动创建 worktree。
- **独立 worktree（TR-15）**：手动启动可勾选「自动创建独立 worktree」，明确起始提交／引用、新分支和「不带入未提交或未跟踪文件」。预览展示解析的 SHA 与受管目标目录，路径参数按起始提交中的对象检查，拒绝符号链接。先持久化目录、分支和 SHA 的预留记录，再复用现有 worktree 管理创建；创建或后续预检失败不会提交模型，保留可检查的记录和已创建目录。同 requestId 不重复创建；重启不自动重试。新目录会再次校验路径、Skill、HEAD 和未提交文件。未提交改动审查不能使用此选项。完成、失败或中断后均保留 worktree；使用记录中的「清理 worktree」需要显式确认，拒绝未提交文件和运行中的任务，仅移除受管目录，保留分支、聊天与记录。

## P2 阶段、共享与效果比较

- **结构化阶段（TR-16）**：编辑器支持最多 20 个有稳定标识的阶段，可添加、移除和排序。每项保存名称、要求、副作用范围、进入前审批和重试上限；阶段要求支持既有参数占位符，正文与阶段要求合计最多 40,000 字符。Agent 在同一个新聊天中依次提交被选中的阶段，每次尝试先落盘发送意图，再调用现有运行时。状态为待执行、跳过、待审批、执行中、阶段回复已生成、失败、停止或中断。阶段回复状态来自真实 `prompt_end`，工具证据来自 `tool_end`；引用持久会话条目或工具调用 ID，经主进程检查归属后查看。界面消息的临时 ID 不作证据。没有定义阶段的旧配方保持单次提交；Plan 配方只规划，不启动阶段状态机或自动批准方案。
- **分支与审批（TR-17）**：条件只比较固定参数值，支持类型匹配的「等于／不等于」，不执行表达式、Shell 或模型判定。条件使用实际参数值和稳定单选值；未提供值与空字符串不同，不自动猜测。预览列出执行和跳过的阶段；Agent 的条件未选中任何阶段时阻止开始。审批在进入阶段前等待，批准才提交，拒绝即停止后续阶段；审批保留时间与结果，不能提升工具权限。输入框上方始终显示当前阶段操作，首阶段尚无聊天消息时也可以审批；等待期间不能通过自由聊天、切换模式或更换模型绕过阶段边界。定时运行等待审批时保留原调度锁。
- **副作用与受控重试（TR-17）**：声明只读、可能修改工作区或可能操作外部服务。只读阶段复用 Plan 的查阅命令守卫，仅开放读取、受限 Shell 与提问，拒绝文件修改、浏览器、MCP 和子任务；所有结构化阶段由根会话执行，避免子任务跨阶段继续。工作区与外部范围是模板声明，实际调用仍服从原权限机制，并非新建的操作隔离层。结构化调用期间关闭 SDK 自动错误重试和可能续跑的自动上下文压缩，结束后恢复聊天原设置；上下文超限作为失败保留，不隐式压缩后续跑。仅已确认的运行时失败允许显式重试只读阶段，最多 0–3 次，重新检查目录、路径、Skill、Git 和模型。重试带独立 requestId，重复请求不创建第二次尝试；已完成阶段不重跑。异常抛出、结果不明、停止、中断、工作区修改与外部阶段均不原地重试。定时失败记录不被手动重试改写，需从快照新建任务。每次尝试与证据都保留；重启不恢复审批、不续跑、不重发。
- **团队共享与版本（TR-18）**：在「团队配方库」连接已有项目，默认本机只读，可明确允许写入；复制或新建后选择团队保存位置，保存动作才写共享模板。文件为项目 `.vela/team-task-recipes.json`，`schemaVersion: 1`、最多 100 项／4 MB，通过现有 Git 或共享文件目录交换，不新增云同步服务或账号系统。本机开关只约束本客户端，实际访问权限由仓库／文件系统 ACL 管理。模板正文、阶段、Skill 名称与参数默认值会共享；来源聊天引用、启动设置、运行参数、记录与评价不会写入团队文件。模板 UUID 可移植，应用身份按真实目录区分；修改递增 revision，无变化保持版本，编辑检查 revision 和内容指纹，外部同版本改动也拒绝覆盖。独占写锁避免协作写入冲突；损坏、未知版本或符号链接文件拒绝写入。异常遗留 `.lock` 只提示检查后手动处理，不自动抢锁；版本历史由 Git 与本机运行快照保留。断开连接不删除共享文件或本机快照。
- **效果比较（TR-18）**：已结束的任务可手动评价「已验收／需改进」，附最多 2,000 字符说明；默认未评价，不从回复内容判断。使用记录按配方身份与 revision 比较使用次数、回复生成数、失败／停止／中断数、评价样本与平均耗时。耗时从首次启动到最终结束，包含审批与重试等待；跨模型、工作区或任务难度的比较不是受控实验。只有用户评价计入验收数，未评价样本不作为失败，`responded` 不作为成功率。统计与评价仅保留本机，不上传到团队库或遥测服务。

## 记录、版本与恢复

有内容变化的保存增加 revision，无变化保存保持 revision，复制生成新 ID 并从 revision 1 开始。每次运行保存完整模板快照、参数、补充要求、展开正文、实际目录、模式、模型、思考强度、权限和 Git SHA。编辑或删除模板不影响历史快照，删除后的历史仍可从「全部使用记录」查看。记录每页 20 条，不自动裁剪。

记录状态是 `starting`、`running`、`waiting_for_user`、`responded`、`failed`、`stopped` 或 `interrupted`。审批与提问使用真实事件；结束状态来自初始运行时调用。`responded` 表示单次任务或所选阶段的回复已生成，不表示任务验收通过。显式只读阶段重试会继续同一条配方记录，保留失败尝试并清除旧评价；后续自由聊天和批准计划不改写原记录。

每个启动请求有稳定 requestId。主进程先原子持久化记录与预留 conversationId，再创建对话、保存绑定和发送意图，最后提交正文。同 ID 不允许不同输入，重复请求不会创建第二个对话或再次提交。绑定写入失败也保留预留 ID；无法保存确认结果时停止重试并显示中断。启动过程中没有消息发送意图落盘，就不提交给 Agent。

重启把未结束的记录标为中断，不自动重发。若对话 JSONL 已写入但索引／绑定写入失败，运行时按预留 ID 对账并恢复关联，不启动模型。用户可打开聊天检查，也可使用快照创建另一项任务。停止不回滚已经发生的文件或外部操作。同一实际目录并发会显示提示，配方不提供文件隔离，也不承诺外部操作 exactly-once。

用户模板和记录在 `~/.vela/task-recipes.json`，服从 `VELA_USER_DATA` 覆盖，独立于模型凭据；内置模板随应用打包。文件包含 `schemaVersion: 1`，写入串行、临时文件原子替换，关键步骤等待 fsync 完成。损坏或未知版本停止写入，界面显示错误与重试，保留原文件。

## 验证与边界
