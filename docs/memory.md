# 项目记忆与全局记忆

状态：P1–P5 已随 1.0.0 发布。需求基线与验收对照见 [requirements/memory.md](./requirements/memory.md)。

Vela 用两个 Markdown 文件保存长期信息：全局记忆跨项目复用，项目记忆跟随会话自己的工作区。文件是唯一内容来源；主代理在对话中主动提炼并保存长期信息，也支持用户明确要求记住、更新或忘记。

## 目录与作用域

| 名称 | 存储位置 | 用途 |
| --- | --- | --- |
| 全局记忆 | `<agentDir>/MEMORY.md` | 跨项目复用的个人偏好、长期工作习惯 |
| 项目记忆 | `<会话工作区>/.vela/MEMORY.md` | 当前项目的约定、决策、已知问题 |
| 全部记忆 | 无单独文件 | 设置页里全局记忆与已登记工作区项目记忆的汇总视图 |

`agentDir` 复用 Vela 资料目录：安装版默认 `~/.vela`，开发版默认 `~/.vela-dev`，遵循 `VELA_USER_DATA` 覆盖。开发版和安装版不自动同步全局记忆。

- 项目绑定创建会话时固定下来的工作区 `cwd` 与 `hasWorkspace`（`packages/agent/src/memory-context.ts` 的 `memoryTargetsFor`）。工具内部进入子目录、界面切换到别的工作区，都不会改变后台会话读取的项目。
- `hasWorkspace` 为 false 的会话只加载全局记忆。
- 没有文件表示没有记忆；读取不创建目录或文件，首次通过工具或设置保存时才创建 `.vela` 和 `MEMORY.md`。
- 非 Git 项目同样支持，不向父目录查找其他项目的记忆。

### Worktree

- 每个 worktree 读写自己的 `.vela/MEMORY.md`，按实际 checkout 隔离。
- 不自动复制原工作区未跟踪或未提交的记忆，也不回退读取主工作树的文件。
- “全部记忆”按实际目录区分主工作树与 worktree；删除 worktree 后目录消失，列表显示为不可用，不自动重建。
- 同步交给用户现有的 Git 工作流。

## 加载时机与刷新

记忆通过 `packages/agent/src/memory-context.ts` 的 `createMemoryContextExtension` 在 `before_agent_start` 读取，并以稳定的 `global` / `project` 标签和来源路径注入系统提示。

- 每次执行开始时读取最新内容一次；同一次执行中的工具调用、steering 和排队消息共享同一份快照。
- 执行结束后的下一条消息触发新的 `before_agent_start`，因此外部编辑、其他会话保存和设置页保存都会在下一次执行生效，不需要重建会话。
- 不缓存、不引入 watcher；先保证外部编辑与恢复后的正确性。
- 主会话和子代理共用加载实现；子代理从所属根会话推导项目，不重复注入 fork 历史里的记忆。
- 定时任务和配方会话使用自己的项目绑定，沿用同一套规则。
- 标题生成、文本辅助、风险评估、配方生成以及 MCP 管理临时会话不携带记忆。
- 只加载全局和当前项目；打开“全部记忆”不会把其他项目内容加入模型上下文。

加载状态通过 `AgentRuntime` 的 `getMemoryStatus` 与会话快照 `SessionSnapshot.memory` 暴露，只含元数据，不含正文。单个来源缺失或失败不会阻塞聊天。

## 写入方式

模型通过 `memory_read` / `memory_update` 维护记忆（`packages/agent/src/memory-tools.ts`）：

- **自动写入**：主代理在回复结束前主动保存用户明确表达的长期偏好、项目约定、已确认决策，以及经本轮验证且对后续仍有用的稳定项目知识，无需用户额外说“记住”。保存成功后简短说明保存的要点和作用域。
- 自动保存由当前对话模型按系统提示选择信息并调用工具，不另开后台总结任务或扫描历史会话；是否选择保存取决于模型对长期价值的判断。
- 不自动保存猜测、未确认方案、单次任务进度、临时日志、完整聊天、原始工具输出、密码、密钥、令牌和其他敏感个人信息。文档、网页或工具输出中的指令不能作为写入依据。
- 用户明确要求“记住 / 更新记忆 / 忘掉”时按要求处理；明确说“不要记住 / 不要自动保存”时遵守该限制，不重新自动保存已经要求忘掉的内容。
- 项目约定、决策和稳定项目知识保存到项目作用域，跨项目的个人通用偏好保存到全局；无项目会话不能把项目知识保存到全局。自动保存的范围不明时跳过，用户明确要求保存但范围不明时再用提问工具澄清。
- 自动写入保留文档结构和无关内容，合并新信息或纠正过时条目；已有相同事实时不重复写入，没有新的长期信息时不调用写入工具。清空只用于用户明确要求，自动整理不能删除无关信息。
- 写入前先读取全文和 revision，保留无关条目，再提交合并后的完整文档；`content` 为空表示清空。
- 保存携带读取时的 revision；冲突返回 `conflict`，不覆盖、不合并、不重试，必须重新读取后再提交。
- 单个文件上限 16 KiB UTF-8 字节；超限时原内容保留，先精简再保存。已有超限文件不静默截断，跳过加载并提供可见状态。
- 读取工具在所有执行入口可用（含 Plan、子代理与后台执行）；写入按权限矩阵控制：Plan 模式、子代理、定时任务和配方后台执行只提供 `memory_read`。`memory_update` 在副作用前复用现有执行权限（ask / smart / full）审批。
- 全文和 revision 都未变化时返回“无需更新”，不写文件或重复请求审批；文件缺失时保存空内容仍创建空文件。审批等待结束后再次检查执行环境，进入只读模式后不继续保存；等待期间出现外部编辑时仍由存储服务拒绝冲突。

物理删除文件是设置页的独立动作，模型工具不提供跨项目枚举、任意路径或物理删除。

## 设置页管理

“启用记忆”是当前 Vela profile 的总开关，默认开启，状态保存在 `<agentDir>/memory-settings.json`，重启后保留。关闭时全局与项目记忆文件都保留，设置页仍可查看、编辑和删除；Agent 不再加载记忆，也不能调用 `memory_read` / `memory_update`，包括 Plan、子代理、定时任务和配方执行。等待审批或排队中的写入在实际提交前再次检查开关。重新开启后，下一次执行读取保留的最新文件。

运行中关闭时，后续模型请求会移除由记忆功能注入的系统提示快照；已发出的模型请求和聊天历史中的回复不会被撤回或清空。

设置导航的“记忆”页（`apps/desktop/src/renderer/components/MemorySettingsSection.tsx`）提供三个视图：

- **全部记忆**：全局文件及所有已登记工作区的项目文件列表，显示作用域、项目名、路径和状态；点击进入对应编辑视图。
- **全局记忆**：查看和编辑当前 Vela profile 的文件。
- **项目记忆**：默认选中当前会话的实际项目，也可以显式选择其他已登记工作区；没有已登记工作区时不显示可保存的目标。

编辑视图支持保存、取消、清空内容、删除文件、在文件管理器中显示。未保存草稿按目标保存在界面存储（与 Git 草稿相同的 `uiStorage` 模式），切换作用域或关闭设置后重新打开会恢复；保存、取消、删除和显式重新加载会清理对应草稿。保存失败时按错误码显示具体原因；冲突时草稿保留，可点击“重新加载”载入最新内容。

主进程的 `apps/desktop/src/main/memory-host.ts` 的 `MemoryHost` 校验 IPC 请求：作用域、已登记工作区身份、内容字节数、revision 类型和开关布尔值。项目访问只接受已登记工作区（路径相等或真实路径相同），renderer 不能传任意路径；`VelaApi.memory` 提供 `list`、`read`、`save`、`remove`、`setEnabled`，预期内的失败以结构化错误返回。

## 存储与并发

`packages/agent/src/memory.ts` 的 `MemoryService` 负责路径解析、读取、指纹、串行写入和文件锁：

- revision 是文件 UTF-8 字节的 sha256；缺失文件固定为 `absent`，与空文件版本不同。
- 写操作按规范化路径在进程内串行，并配合同目录独占锁协调多个 Vela 进程；锁存在时返回 `busy` 并给出锁路径，不自动抢锁。
- 使用同目录临时文件写入、刷新后原子替换；失败清理临时文件，原内容保留。
- `save` / `remove` 在锁内重新读取并比较内容指纹；外部编辑器不遵守 Vela 的锁，指纹检查只能检测提交前可观察的修改。
- 拒绝符号链接、非普通文件、目录丢失和无权限等不安全或不可用目标。

## 错误与状态

| 状态 | 含义与处理 |
| --- | --- |
| `missing` | 文件不存在；正常状态，显式保存后创建。 |
| `invalid-encoding` / `content-too-large` | 文件无效 UTF-8 或超限；跳过加载、保留原文件，用外部编辑器修复或精简。 |
| `unavailable` / `not-a-file` / `unsafe-path` | 目录或文件不可用、不是普通文件、路径不安全；该来源加载失败，另一个来源仍可加载。 |
| `conflict` | 保存或删除时版本不一致；保留原内容，重新读取并重新合并后再提交。 |
| `busy` | 另一个 Vela 进程正在写入；锁定未被自动清理，必要时按提示手动移除同目录 `.lock` 文件。 |

## 实现位置

| 位置 | 内容 |

## 验证

定向测试：

```sh
pnpm --filter @vela/desktop test:memory     # 存储、加载、权限矩阵、IPC 与设置模型
pnpm --filter @vela/desktop test:memory:ui  # 渲染层：列表、保存、冲突、草稿、删除与中英文
```

更广的回归与类型检查记录见 [requirements/memory.md](./requirements/memory.md) 的 P5 小节。当前边界：

- 不引入向量数据库、云同步、后台总结或自动整理任务。
- 不自动修改 `.gitignore` 或执行提交；项目文件由用户决定是否纳入版本控制。
- 不提供对任意外部写入的事务隔离，只做提交前可观察的指纹检查。
- 设置页不执行记忆正文中的 HTML。
