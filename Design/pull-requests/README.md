# Pull Request HTML 设计稿

入口：[pull-requests-preview.html](../pull-requests-preview.html)。文件自包含，可离线打开，无第三方字体、图标或脚本请求。

正式实现方案见 [Pull Request 中心：GH CLI 实现方案](../../docs/requirements/pull-requests.md)。GitHub 访问统一经过 gh，包含需要分页或补充数据时的 `gh api`；当前 HTML 仍使用本地模拟数据。

## 设计范围

为 Vela 左侧导航增加 Pull Request 入口。沿用项目的冰蓝侧栏、白色内容纸面、系统字体与克制的圆角，详情结构参考用户提供的概览和代码变更截图。

“与我关联”暂按四种关系设计：本人创建、请求本人审查、分配给本人、讨论中提及本人。这是本轮设计假设，不代表 GitHub 接入范围已确认。同一 PR 在真实产品中可能同时具有多种关系；这轮模拟数据每条只配置一种。

主链路：侧栏入口 → 关联列表 → 选择 PR → 概览 / 变更 → 选择文件或打开审查设置 → 返回保留筛选的列表。

- 列表：关系筛选、关键词搜索、仓库筛选、状态筛选、排序。默认显示打开和草稿中的 PR，将冲突、失败检查和待本人审查的条目放在“需要关注”。
- 概览：状态、完整标题、作者、源 / 目标分支、说明、测试计划与活动；右栏展示合并状态、审查与检查结果。
- 变更：单文件 diff、行号、增删高亮、上下文折叠条、文件筛选；保留右侧文件目录和底部提问入口。
- 审查入口：可打开范围设置，选择全部变更或当前文件。
- 窄窗口：隐藏侧栏并提供导航按钮，列表状态移到标题下方，详情右栏顺排，变更文件通过下拉选择；代码长行仅在代码区域横向滚动。
- 键盘：Tab 焦点、原生选择框、详情标签的左右键、⌘/Ctrl K 搜索、⌘/Ctrl B 侧栏开关、Escape 返回。

## 数据与操作边界

所有 PR、检查结果、活动和 diff 均为本地模拟内容。DeepTutor #1553 的主要内容来自参考图，仍应视为设计样本，而非实时 GitHub 状态。其余条目与账户连接状态为模拟内容。

筛选、导航、文件切换、弹窗和侧栏开关在本地实际运行。刷新只重绘模拟数据；审查、冲突修复、提问未接入 Vela；合并禁用。复制链接与外部 GitHub 入口保留浏览器能力。真实认证、权限、同步、未连接 / 加载 / 失败状态、评论提交和多重关联数据模型尚待产品实现。

## 评审与验证

风险分类：仅新增独立设计文件与说明，未修改应用运行代码或依赖。对设计稿进行 JavaScript 语法检查与定向浏览器检查，无需回归测试、应用构建或类型检查。

已在浏览器查看 1440 × 960 桌面和 390 × 844 窄窗口，并检查 720 × 480 的放大等效重排；未单独执行浏览器原生 200% 缩放。

定向检查：默认 7 条；“我创建的”4 条、“待我审查”1 条；VelaHarness 仓库筛选3条；已合并状态1条；无匹配结果和重置筛选；详情与返回列表；文件切换、文件搜索空结果、窄窗口文件下拉；审查弹窗；详情标签左右键；窄窗口侧栏开关。浏览器未记录控制台错误。全页无水平溢出，长代码在局部滚动。

独立评审者实际查看了桌面列表、概览和变更三张截图。沿现有产品规范进行一轮评审，不作审美评分。接受并修正：长文件名单行省略并保留完整路径提示、目录按路径段换行、合并阻塞文字、未完成检查的“运行中”状态、辅助信息对比。删掉列表标题下的重复说明、右栏重复同步信息；“其他 Pull Request”缩为“其他”。修正后的画面由主 Agent 复查。
